# Active typed record round and account lifecycle

Standing authorization under the active-runtime plan. Own only new sync/record_round.rs, record_account.rs, their tests, this plan and the ledger. Root owns registration, common state pending field/validation, native wrappers and dispatch; key worker owns local vault import/generate. Preserve other workers' edits. No legacy files/slots/agent materialization paths.

1. Define a public, secret-free PendingAccountOperation and validator first, then root wires the optional durable state field. Stable operation/account/space IDs and prepared ciphertext/public caches carry accepted receipts; staged mnemonic stores only a strict operation-specific Keychain account name. No raw code/token/encryption key/private text in state or journal.
2. TDD isolated copied crate/unregistered new modules: account gate every round from fresh pull since0, schema4/pending/invalid retain exact sections and durably block shared writes; failed gate save sets in-memory save_blocked; only authenticated compatible proof clears. Selected spaces use baseline0/current cursors, then dirty outgoing and exact receipts; unselected spaces untouched. No doc/files/agent tail. No stale whole-state commit under concurrent edits.
3. Serialize structural account lifecycle with lifecycle mutex and background rounds with syncing guard. Pure section transforms apply to latest core; publication mutex orders gate observation with material transaction. Do not hold core/doc/vault during network or Keychain callbacks. Snapshot/recheck account chain and relay identity before committing evidence. Native shared CRUD obtains a fresh proof before Repo edit; known unsupported accounts may poll only account.
4. New schema3 account create and compatible join preserve local records. Old schema2 join returns migration-needed before staging/mutation/Keychain. Persist pending operation before remote/credential effects; resume fixed IDs and accepted ciphertext. State save/Keychain/relay failures preserve pending progress; fresh gate before shared publication. No automatic relay deletion or old-account upgrade.
5. Space create/rename/select and explicit key publish use fresh account proof, validated public payloads, sealed credentials/private payloads, baseline before push, then exact receipts. Key publish is explicit; key activation remains separate worker's validated/journaled vault responsibility. No shared private text in DTO/state/logs.
6. Explicit synced download delegates to the vault worker's activate_synced under caller-held lifecycle: fresh public account metadata, zeroizing private copy, new vault ID and public/revision CAS; conflicts never overwrite old material. Stop sync only tombstones the sealed Key, retaining public keyslot and local Vault. Background failures expose a fixed non-secret diagnostic without overwriting format/storage gates.
7. Scratch RED->GREEN, root registration, focused formal tests only, exact-path conventional commit with index flock. Root performs integrated full gates and independent final review once active wiring is complete.
8. After this basic commit, separate focused leave/rotation plans fulfill binding spec acceptance: selected usable records copied to Local with ID/jump/password namespace remapping, no remote delete; records rotation copies typed schema2 hosts/keyslots and sealed material with migration/pending exclusion, never legacy files/slots. No actual user leave/rotation/migration is executed.

Client preflight cannot provide atomic cross-chain relay freeze; document each partial-success boundary and retry cost. This plan does not run any real migration or real Keychain/relay/vault access.
