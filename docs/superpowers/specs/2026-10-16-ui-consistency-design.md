# SSHelter 全介面一致性改版規劃

日期：2026 年 10 月 16 日。狀態：設計基準與分批實作規劃；各批完成狀態及驗證限制見[實作紀錄](../../2026-10-16-ui-consistency-implementation.md)。

SSHelter 的介面應收斂成一套安靜、緊湊、可預期的 SSH 桌面工作環境。沿用已確認的中性灰表面與節制藍色，讓主機、金鑰、同步、匯入、設定與授權共用明確的版型和操作規則。這次改版的核心是統一資訊層級、位置、行為與動態回饋，讓使用者切換功能時不必重新理解介面。

主線以 Records Library 為準；Legacy 模式仍共用基礎視覺元件，但保留 OpenSSH 檔案管理的功能邊界。以下尺寸為 root font size 15px 時的設計基準，實作須沿用現有 13–17px 文字大小設定並重新排版。

## 目前問題與原因

目前已經有共用色彩和 Radix 元件，卻沒有共用完整的頁面結構。這讓單一元件看起來相近，組合起來的頁面仍然不同。

| 問題 | 目前證據 | 改版處理 |
| --- | --- | --- |
| 頁面尺度不同 | Hosts 的標題為 `1.65rem`，Keys、Sync 使用 `text-lg`；Hosts 滿寬，工具頁各自包 `max-w-3xl p-6` | 所有主頁共用 PageHeader、頁面邊界與內容模式 |
| 同層資訊採用不同容器 | Hosts 有群組卡片、主機卡片和詳情；Keys 每把金鑰展開一張表單卡；Sync 疊加多種流程卡 | 資產採列表與詳情，流程採步驟與審閱，偏好採設定列 |
| 密度隨頁面變動 | Library 自訂標題、搜尋、圖示底座與圓角；設定又有 grouped inset，Records 表單另有 `RecordField` | 建立有限的文字、間距、尺寸與表單規格 |
| 操作層級混雜 | 連線同時出現在列表、詳情和命令面板；Keys 的新增表單在頁面內插入；主機新增則是 dialog | 保留合理的多入口，但相同操作共用入口名稱與流程 |
| 狀態缺乏一致表達 | Sync 有 footer、全域 notice、頁內錯誤；Hosts 的 readiness 與信任、連線結果又是不同意義 | 狀態依作用範圍呈現，同一狀態只保留一個主要解決入口 |
| 周邊視窗風格分散 | 主機編輯、金鑰授權、驗證、指紋確認各自安排標題、內容與底部按鈕 | 共用視窗骨架，保留每種安全決策的獨立語意 |

## 設計原則

1. **先看物件，再看操作。** 主機先呈現名稱、目的地與可用性；金鑰先呈現名稱、類型與本機可用狀態。進階細節在選取後出現。
2. **同一層級使用同一語言。** 主頁標題、區塊標題、欄位標籤、輔助說明各有固定規格，不能每頁自行設計。
3. **重複資料用列呈現。** 預設使用列表，避免每個物件都帶大型圖示、邊框、底部工具列。既有卡片檢視保留為次要選項，兩種檢視使用同一資料與動作。
4. **藍色對應操作和選取。** 裝飾圖示、資料夾、一般標籤保持中性。狀態色只表達成功、需處理與錯誤。
5. **資訊隨任務展開。** 常用資料先出現，來源、繼承、診斷與技術說明可展開；阻擋操作的原因必須直接可見。
6. **統一外觀，也統一行為。** 選取、搜尋、返回、儲存、取消、失敗重試和鍵盤焦點都要可預期。
7. **用動畫交代變化。** 側邊欄、群組與詳情的開合呈現空間關係；操作回饋迅速可見，使用者可以連續操作，不必等待動畫播放完畢。

## 資訊架構

沿用現有主要入口，先改善其層級與關係。介面保留英文，規格使用中文；新增文案採 sentence case。

```text
SSHelter
├─ 全域標題列：應用名稱、Quick connect、工作區選單
├─ Library
│  ├─ All hosts
│  ├─ Recent                 主機的時間排序視圖
│  ├─ Needs attention        主機的問題篩選視圖
│  └─ Keys
├─ Groups                   主機的資料夾與繼承階層
├─ Tags                     跨群組的主機篩選
├─ Tools
│  ├─ Import hosts
│  └─ Sync
└─ Settings
   ├─ General
   ├─ Appearance
   ├─ Connection
   ├─ Local data             Records；Legacy 保留檔案與備份選項
   ├─ AI access
   ├─ Updates
   └─ Advanced
```

Library 是單一工作區的標示。現有介面只有一個 Library 時，不把它畫成可切換的 workspace picker。移除重複的「Your SSH workspace」與 Hosts 頁宣傳式副標，讓視覺焦點回到內容。

Groups 與 Tags 是篩選和組織方式，不和 Keys 混成同一層的產品功能。Sync 頁是同步設定與復原的唯一主要目的地；Settings 內既有 Sync 入口在 Records 模式改成導向該頁的捷徑。Local data 的匯入入口同樣導向 Import hosts，不建立第二套流程。AI access 留在 Settings，主機詳情可提供導向特定主機權限的捷徑。

## 四種頁面版型

### 資產列表與詳情

套用 Hosts、Keys，以及 Legacy 可共用的資產列表。固定為 PageHeader、CollectionToolbar、CollectionView、可選的 DetailPane。

單擊選取並顯示只讀詳情；編輯透過明確的 Edit 動作。列上的 Connect、複製等動作不觸發選取的副作用。列表與卡片使用相同排序、名稱、狀態和選取結果，切換檢視不清除搜尋或選取。

### 流程與審閱

套用匯入、同步啟用、加入裝置、升級及遷移。一般狀態採閱讀寬度的單欄；有先後相依的工作才顯示步驟。每步固定標題、必要說明、內容、錯誤區與操作列，審閱結果使用資料列或差異清單。

### 偏好設定

Settings 保留獨立 modal，讓偏好設定與目前主機工作維持清楚關係。使用同一表面、文字、導覽選取和表單元件。第三批將最大寬度調整為 62rem（15px 基準約 930px），分類欄 12.75rem，並保留視窗安全邊界。高度不超過 45rem 或視窗扣除 3rem；內容與分類各自捲動，標頭與生效說明固定。

一般切換類偏好維持即時生效；文字或複合設定需要提交時，顯示清楚的儲存範圍。不要在同一區塊混用自動儲存和隱藏的 Save 行為。

### 編輯與決策視窗

主機、Group、金鑰新增或編輯共用 FormDialog；MCP 審閱、金鑰授權、密碼輸入和指紋確認共用 DecisionLayout。一般編輯視窗與獨立原生視窗分別處理容器、焦點和生命週期，不能為了共用外觀而改成同一種授權流程。

## 各功能的目標畫面

### Hosts

- 預設列表，保留卡片切換與既有偏好相容性；若新增持久化，僅新增 UI 偏好。
- 名稱為第一層，`user@hostname:port` 為第二層；Group、Tags 與問題狀態為補充資訊。一般可用主機不反覆顯示醒目的 Ready 徽章。
- 當前 Group 可用 breadcrumb 返回；All hosts 首頁不再重複展示整排大型 Group 卡，Group 的瀏覽入口集中到左側。保留群組編輯與子群組導覽。
- 頁首主操作是 New host，旁邊選單提供 New group；匯入導向既有 Import hosts。
- 列上保留低強度、可直接取得的 Connect，更多操作收於同一選單。選取後詳情的 Connect 可為主要按鈕，但整排列表不鋪滿藍色按鈕。
- 批次選取時，工具列顯示數量、移動、標籤與移除；退出後還原搜尋工具列，避免另加一層永久工具列。
- 詳情固定依序顯示物件摘要、連線、驗證、Group 與繼承、Tags、進階與診斷。缺少金鑰或繼承問題直接帶到可修正的位置。
- Group 編輯明確顯示繼承值和本機覆寫值；停用繼承的選項放在欄位旁，避免未標示來源的有效設定。

### Keys

- 採與 Hosts 相同的列表與詳情，不在每把金鑰卡片中攤開所有按鈕和表單。
- 列表顯示名稱、演算法、本機是否可用、是否分享；本機缺少材料與禁止分享是兩種不同狀態。
- 選取後顯示 fingerprint、引用該金鑰的主機、本機材料、分享設定與可用操作。
- 主操作 Generate key；次要入口 Import private key。兩者使用一致的 FormDialog，取代插在清單上方的新增表單。
- Copy public key、Deploy to host 等動作依現有能力提供。分享、停止分享、下載與刪除要清楚說明對目前裝置及其他裝置的影響。
- 私鑰或同步碼不因視覺預覽、清單摘要或狀態提示而暴露；全文 fingerprint 可複製及換行，摘要可縮寫。

### Sync

頂部顯示一個權威的同步狀態與必要操作，下方依序為 Library 範圍、Devices、Key sharing 說明與進階設定。金鑰分享的實際開關集中在 Keys，Sync 提供連結和摘要，避免兩套編輯狀態。

未設定時提供 Create sync 與 Join existing sync，完成選擇後才展開對應流程。待完成、暫停、失敗與格式升級各顯示一個當下可執行的主要動作。Relay URL、復原與帳戶生命週期放在進階區；退出或輪替等高影響操作保留明確審閱。

Footer 顯示「未設定／同步中／上次成功／需處理」的簡短結果。只有阻擋共享變更時才在工作區顯示 notice；完整原因與恢復流程集中在 Sync。

### Import hosts 與遷移

流程為選擇來源、預覽與選擇、確認結果。預覽使用共用資料列，讓使用者先確認主機與阻擋連線的問題，再選擇是否複製金鑰。來源檔案、digest 和不支援的指令可展開，會影響連線的警告保持可見。

部分完成時保留收據、成功項目和待完成項目，重試只針對未完成部分。Legacy 遷移、格式升級、Library 衝突審閱使用同一流程版型，但各自保留現有審閱 token、版本與確認範圍。

### Settings 與 AI access

設定分類名稱按模式提供實際可用內容，Records 不顯示會讓人誤以為正在編輯 OpenSSH 原檔的說明。移除只作跳轉卻看似另一套設定的重複頁面。

AI access 頁內分為連線設定、主機權限、近期活動。主機權限清單沿用搜尋與資料列；Ask、Auto-log 保留既有決策與確認方式。主機儲存成功不會自動授權 AI，授權 AI 也不等於信任伺服器金鑰。

### 授權與驗證視窗

共用標題、來源／目的地、待確認內容、提示、操作列。MCP 顯示實際 client、有效目的地與完整命令；金鑰授權顯示請求來源與 fingerprint；新指紋與指紋變更保留不同風險語意。

按鈕文字使用具體動作，例如 Allow once、Deny、Trust and connect。高影響決策不將同意設為預設 Enter 行為；保留現有後端 gate、失效時間與拒絕／取消語意。相同外觀不代表共用同意範圍。

### 更新與診斷

Updates 使用設定版型，依序呈現目前版本與 channel、檢查結果、release notes、下載與安裝狀態。安裝期間的禁止關閉與提示沿用現有規則。主工作區僅提供低干擾的更新入口。

診斷以問題清單、受影響物件、修正入口為核心；可複製技術資訊，錯誤不只用 toast。Legacy 的 known_hosts、備份、檔案檢視、探索與 linter 使用共用 DialogHeader、工具列、資料列和錯誤樣式，保留各自功能。

## 視覺規格

### 色彩與表面

保留 `src/index.css` 現有 light／dark 色盤作為起點，經過實際畫面與對比檢查後調整。所有頁面與 portaled menu、tooltip、dialog、toast 共用同一組語意 token，不增加 Library 專屬色盤。

| 角色 | 用法 |
| --- | --- |
| `surface-canvas` | 主內容底色，對應現有 background |
| `surface-navigation` | 導覽欄，對應 sidebar |
| `surface-raised` | 選單、對話框及必要的分組表面，對應 card／popover |
| `text-primary`／`text-secondary` | 主要內容與輔助內容，對應 foreground／muted-foreground |
| `border-subtle`／`border-control` | 結構分隔與輸入控制項，對應 border／input |
| `action`／`selection`／`focus` | 共用藍色來源，分別控制按鈕、低強度選取背景與焦點框 |
| `status-success`／`status-warning`／`status-danger` | 共用狀態色；補齊 token 後避免頁面自行使用綠、黃、紅色值 |

資料列、欄位群組與章節主要靠對齊、留白、細分隔線區分。邊框和陰影只用於需要清楚邊界或浮起的表面。避免大面積玻璃效果和重複的圖示底座。

### 文字與間距

| 項目 | 基準 |
| --- | --- |
| 頁面標題 | 約 20px，600 字重；所有主頁一致 |
| 詳情物件名稱 | 約 16px，600 字重 |
| 區塊標題、一般內容與控制項 | 約 13px；一般 400，強調 500–600 |
| 輔助說明與欄位標籤 | 約 12px；必要內容不靠極小字壓縮 |
| 字體 | 保留系統 sans；主機位址、fingerprint、路徑與命令使用既有 mono |
| 間距階梯 | 4、8、12、16、24、32px，轉成可縮放 token |
| 圓角 | 控制項 6px、分組 8px、浮層 12px；不按頁面新增圓角規格 |
| 圖示 | Lucide 同一線條風格；一般 16px，輔助 14px；移除無任務用途的大圖示 |
| 動態 | 共用 80／120／180／220ms 時間階梯，依下節的觸發與用途選用；支援 reduced motion |

### 控制項與操作層級

一般按鈕與輸入框基準高 32px，緊湊圖示操作 28px；不可隨頁面任意混用高度。按鈕分為主要、次要、低強度、危險四種語意，沿用既有 Button primitive 的變體實現。

每個獨立任務區塊最多一個主要動作。表單的取消與提交固定在底部；浮層底部保持可見。高影響操作遠離一般動作，確認內容包含具體對象與影響範圍。

表單標籤固定在上方；偏好設定才使用左側說明、右側控制項的設定列。Help text、錯誤訊息與控制項建立可及性關聯，必填欄位、繼承值及覆寫值有一致標示。

## 動態與轉場規格

動畫是整體設計系統的一部分。優先處理會改變空間配置、導覽位置及操作狀態的介面；背景刷新和一般資料呈現保持穩定。以下時間是起始設計值，須在原生 WebView 的實際畫面中校正。

### 側邊欄

新增全域標題列的側邊欄展開／收合按鈕。預設為 208px 的完整導覽，收合後為 56px 的圖示列，主內容同步取得騰出的空間。按鈕在兩種狀態都保持可見，位置不跟著內容跳動，具有清楚的 accessible name、`aria-expanded` 與 `aria-controls`。

- **展開與收合**：220ms；側欄寬度與內容區的邊界協調過渡。文字在約 80ms 內淡出或淡入，圖示保持原尺寸，不能把整欄橫向縮扁。
- **內容穩定**：文字在過渡期間保持原本的行寬並裁切，避免逐字換行。只讓必要的版面區域重新配置；列表、詳情和工具列不各自追加一套位移動畫。
- **收合狀態**：保留主要功能圖示、選取標示、可及名稱與 tooltip。Groups、Tags 的完整階層在展開後閱讀，展開入口始終可取得。需要處理的狀態仍有文字替代與可辨識標示。
- **選取切換**：同一導覽區內的選取底板可用 120ms 移動或色彩過渡；跨區、重排或目標不可見時直接更新選取，避免底板橫越其他項目。焦點框和當前頁語意立即更新。
- **群組開合**：為有子群組的節點新增獨立 disclosure 按鈕；點名稱仍是瀏覽該 Group。子樹以 180ms 展開／收起，箭頭以 120ms 旋轉，隱藏內容不能繼續被鍵盤聚焦。
- **連續操作**：再次點擊時從當前呈現位置反向，不排隊播放，也不將按鈕鎖到動畫結束。保留導覽捲動位置、選取與開合狀態。
- **首次載入**：直接呈現已保存的展開狀態，不先播放一次開場動畫。保存的是 UI 偏好；Records 的 Group 開合使用自己的 ID 命名空間，與 Legacy 的來源檔案開合分開。

目前 Records 導覽欄是固定寬度，子群組直接展開呈現；上述開合控制屬於這次提案新增的互動。Legacy 已有的拖曳寬度與群組開合則採用相同動態語言，保持各自的導覽資料模型。

### 其他需要動態回饋的介面

| 元件或情境 | 動態 | 行為要求 |
| --- | --- | --- |
| 右側詳情欄開關 | 220ms，邊界過渡搭配最多 12px 位移與淡入淡出 | 列表同步讓位；關閉後回到原選取入口；換主機時保留欄寬，不重新播放整欄入場 |
| 進階設定、診斷及表單區塊開合 | 180ms 展開高度，箭頭 120ms | 內容按實際高度展開；展開後可鍵盤操作，收起時移除隱藏焦點目標 |
| Menu、popover、命令面板 | 120ms 淡入，必要時最多 4px 位移 | 從觸發位置呈現；鍵盤操作立即有效；避免整個列表逐項出場 |
| 編輯和設定 dialog | 進入 180ms，離開 120ms；淡入淡出搭配 0.98 到 1 的輕微縮放 | 一次只讓最上層浮層主導視覺；不彈跳；保留焦點管理和取消語意 |
| 頁面與詳情內容切換 | 最多 120ms 的內容淡入；版面骨架維持原位 | 不將整個主頁左右滑動；新資料、選取和操作狀態立即生效，不等待轉場 |
| Hover、按下、勾選、複製完成 | 約 80–120ms 的色彩或圖示變化 | 先給操作回饋；提交成功只在真正完成後顯示；確認訊息可被輔助技術讀取 |
| 批次操作列、儲存列和 inline notice | 120ms 淡入淡出，必要時平順展開所需空間 | 內容不遮住資料或焦點；會阻擋操作的錯誤立即可見 |
| 同步、下載與連線處理中 | 處理期間的進度或 loading 動態 | 由真實任務狀態控制；沒有百分比資料時使用不定進度，不偽造進度；完成或失敗即停止 |

拖曳調整欄寬、視窗 resize 與斷點切換採即時回饋，不加寬度動畫或回彈，讓分隔線始終跟著指標。側欄開合導致詳情進入 compact 模式時，按目標寬度協調一次切換，不在過渡過程中來回切版。

搜尋結果、背景同步後的資料刷新、時間文字和整批列表首次呈現不播放逐列動畫。刪除或新增只在必要範圍給予簡短回饋，不讓其餘物件反覆飛入，也不藉動畫改變排序或延後顯示錯誤。原生獨立視窗的出入由作業系統管理，不再疊加整個視窗的 DOM 縮放動畫。

### 共用參數與實作邊界

共用時間 token 為 `motion-instant` 0ms、`motion-feedback` 80ms、`motion-fast` 120ms、`motion-content` 180ms、`motion-layout` 220ms。進入與版面變化以 `cubic-bezier(0.2, 0.8, 0.2, 1)` 為起點，離開以 `cubic-bezier(0.4, 0, 1, 1)` 為起點。整個產品使用同一組參數，功能頁不自行引入彈簧或彈跳曲線。

以現有 CSS、Radix 與瀏覽器動畫能力實現，先不新增動畫套件。明確指定需要過渡的屬性，不使用廣泛的 `transition: all`；opacity 和 transform 優先，寬高只在側欄、詳情及 disclosure 等確實需要改變版面的容器使用。可重用 Disclosure、PaneTransition 與共用動態 token，避免每頁另寫一套生命周期。

狀態與資料更新不依賴 `transitionend` 才完成。動畫中斷、快速反向、視窗最小化、元件卸載或 reduced motion 都必須得到正確的最終狀態；關閉內容立即停止接收互動，開合完成後不能留下透明遮罩或幽靈點擊區。開合過程不重建編輯表單，保留草稿、捲動和焦點。

### 減少動態效果

遵循 `prefers-reduced-motion`，並在 Settings 的 Appearance 提供 System／Reduced 選擇。System 跟隨作業系統；Reduced 明確減少動態，不提供強制覆蓋系統偏好的完整動畫模式。初始偏好必須在第一幀前套用。

Reduced 下直接完成位移、縮放、寬高變化和箭頭旋轉；必要的色彩回饋最多保留 80ms，也可直接更新。不使用 skeleton 掃光、持續旋轉和脈動，仍以文字與非動畫進度資訊表達任務狀態。功能、焦點、狀態提示與可操作時機完全相同。

## 視窗尺寸與可及性

沿用原生最小視窗 800×560。800px 是桌面產品驗收下限，對話中的縮小方向稿另作可讀性調整，不據此改動正式產品的最小視窗。

- 詳情欄沿用既有測量邏輯：視窗至 820px，或內容不足容納列表及詳情各 320px 時，切成單內容畫面。提供清楚返回列表入口，保留選取和位置。
- 保留 400px 的偏好與 320–640px 調整範圍；暫時縮小的實際寬度不能覆寫使用者偏好。保留鍵盤調整及重設。
- 頁首與工具列依空間換行，降低次要欄位而不是縮小文字；不可將關鍵操作全部藏在 hover。
- 全頁不捲動；導覽內容、列表、詳情或 dialog body 各自擁有清楚的捲動區，避免同一閱讀路徑出現雙重垂直捲動。
- 焦點框、選取、禁用與 hover 分別設計；dialog 關閉後回到觸發入口，compact 詳情切換有合理焦點。
- 一般文字及主要按鈕的對比目標為 4.5:1，必要控制項邊界和焦點目標為 3:1；兩種主題各自檢查。顏色同時搭配文字或圖示。
- 覆蓋 root font size 13、15、17px，以及長主機名、長 Group 路徑、中文名稱、IPv6 和長 Terminal 名稱。不得靠裁切欄位解決放大問題。

## 驗收與驗證

建立純假資料的 UI 展示入口，只在開發或測試環境可用，不呼叫真實 SSH、vault、relay 或更新安裝。視覺驗收使用固定 fixture，讓 screenshot 可重現。

**畫面矩陣**：800×560、1100×720、1440×900，light／dark，root 13／15／17px。先對共用骨架完整覆蓋，再以代表性最差內容覆蓋每種版型。macOS、Windows、Linux 都檢查標題列、安全邊界、字體與捲軸，不能只用瀏覽器截圖代替原生確認。

**任務矩陣**：尋找並連線主機、新增及修改主機、編輯 Group 繼承、批次移動／標籤、產生及匯入金鑰、調整分享與部署、啟用／加入／復原同步、匯入及處理部分完成、設定 AI allowlist 與審閱請求、首次及變更指紋確認、更新檢查與下載。

**動態矩陣**：側欄與群組快速反覆開合、開合中切頁、詳情開關與拖曳調寬、側欄導致的 compact 切換、表單帶草稿時開關、動畫中斷和卸載、系統 Reduced 偏好切換及重啟後直接還原。原生 WebView 中檢查轉場順暢、文字不扭曲、焦點不遺失、沒有透明遮罩攔截點擊；背景同步不能觸發整頁重新入場。

沿用現有相關測試，針對重構實際改動的互動補足整合案例；不為單純間距、字級或顏色撰寫鏡像實作的測試。每包執行 `npm run build` 和受影響的 Vitest；共用狀態或事件介面變更時才擴大測試範圍。

完成標準：

- 所有主頁採用既定版型，沒有自行定義的 h1、控制項高度、dialog footer 或主要色盤。
- 三種視窗尺寸及最大文字設定下，沒有被遮擋的按鈕、不可見錯誤或無法取得的完整值。
- 只用鍵盤即可搜尋、選取、開啟、編輯、取消及返回；焦點不遺失。
- 既有連線、同步、匯入、權限與信任決策的語意及邊界一致，草稿與部分完成結果不遺失。
- UI 表面一致性清單涵蓋主工作區、設定、portal 浮層、獨立原生視窗及 Legacy 仍可到達的頁面。
- 側欄、群組、詳情和浮層使用共用動態規則；一般與 Reduced 模式都能立即操作，快速反向不排隊，拖曳調寬沒有延遲。

## 範圍與實作決策

本輪採用的方向是中性桌面工作區、列表優先、可選詳情、單一同步目的地、四種共用版型與統一動態規則。保留現有主要導覽、快捷鍵、深淺主題及文字大小偏好；新增側欄與群組的開合能力和 Reduced 動態偏好。預覽畫面的資料均為示意。

| Workspace | 不另設 Sync 分類 | Sync | Records 使用工作區 Sync；Legacy 的既有 space 管理仍留設定 |
| Maintenance | Updates | Updates | 目前版本、通道、進度、release notes；沿用現有更新生命週期 |
| Maintenance | Diagnostics | Discovery & checks | 共同診斷 log；Records 顯示工作區能力，Legacy 放探索來源、外部變更、lint 規則 |

布林值使用 switch，互斥的小型選項使用可鍵盤操作的單選控制，多個選項使用 select，檔案路徑使用有標籤的輸入與明確 Apply。唯讀資訊呈現為文字，不以 disabled select 偽裝可設定。即時設定不出現多餘 Save；尚未套用的 config path 切頁時保留草稿，關閉前提示。匯入偏好仍先驗證再確認覆寫。

設定列在內容變窄或字級增大時轉為上下排列，控制項不擠壓說明；說明和控制項有可及性關聯。分類切換保持穩定的標題位置，搜尋跳轉要帶入正確焦點與捲動；關閉還原來源焦點。

### 執行與驗收順序

1. 先建立設定的導覽／搜尋索引和共用設定列，完成 Records／Legacy 的分類邊界；搜尋不能洩漏另一模式的不可用設定。
2. 設定的各 pane 重新歸位，移除重複的跳轉分類、唯讀假控制項與空泛 Advanced。AI 主機清單補搜尋、數量及可取得的完整 ID／Group。
3. 共用 Task dialog 支援固定標頭／操作與單一內容捲動，逐個替換上表工具、表單與輔助流程。loading／error／empty／success 採相同規則。
4. Legacy 工作區與 Keychain 接上共用頁首、章節、操作列與 disclosure，保留現有連線與檔案管理行為。
5. 擴充 development-only 假資料入口，覆蓋設定兩模式、Legacy 與次要流程。檢查 light／dark、13／15／17px、800×560／1100×720／1440×900，以及 System／Reduced、鍵盤搜尋跳轉、關閉焦點和長內容。
6. TypeScript、production build、受影響 Vitest 及完整前端測試；確認 production 不含預覽入口。macOS 原生檢查可用環境；Windows／Linux 人工逐畫面驗收另行明確記錄，不以瀏覽器取代。
