# Beta 13：Windows 啟動保護與本機錯誤 log

來源為 `3d39718e085bf3d7db14cc28515d713a4df22c09`，分支 `codex/library-sync-host-dialog-fixes`。安裝包包含 `1db5c2d` 的 tray／診斷、`e37fa9c` 的 Win32 綁定、`8c15cb9` 的完整 Windows GUI 啟動驗證與 PID，以及 `3d39718` 的明確 Windows WebView 建立錯誤處理。後續文件提交不改變安裝包來源。

## 行為

- tray 的建立、lookup、安裝、visibility 與 native handle 生命週期都在主執行緒；初始化先於背景 worker，狀態變動但選單相同時不重建。更新相容的 muda 0.19.3 Windows patch。
- Windows 主視窗改由既有入口明確建立，捕捉一般建立失敗並顯示原生提示、留下 log；背景 host 延後建立主 WebView，broker 繼續運作。macOS 保持既有 CoreAudio 原生 guard。
- app.log 為本機輪替 JSON Lines，包含時間、PID、版號、profile、階段、固定錯誤分類與 panic 程式位置／backtrace；Windows 另有 best-effort native-crash.log，不產生 memory dump。每種檔案目前檔＋兩代，各 256 KiB。資料保留跨重啟，不上傳 hosts、credentials 或同步碼。
- 設定 → General → Data → Open logs；正式 Windows 路徑為 `%LOCALAPPDATA%\org.homelab.sshelter\diagnostics`。
- Records 編輯與同步保存 SSHelter 資料；Legacy 工作區維持原本 SSH config 編輯行為。session、pin 核准與金鑰授權規則未更動。

## 限制

使用者回報原本錯誤電腦更新後已能同步，另一台 Windows Beta 12 啟動閃退的確切根因仍未取得足夠證據；10000／10010 是事件識別碼，不等於 SSHelter exception／module 證據。此次修正已確認的執行緒與啟動錯誤路徑並提供診斷，仍待故障機更新驗收。

原生 filter 可能被覆寫，fast-fail、強制 kill、嚴重 stack 損壞與 WebView2 子程序 crash 不保證可捕捉。`ready`／HWND／React mounted 均不能單獨證明 GPU 正常繪圖。尚未對使用者正式 Windows 執行 updater 安裝／重新啟動，未逐平台安裝所有產物。

macOS guard 可避免可偵測的啟動前 CoreAudio 無回應變成無提示黑畫面，沒有根除系統音訊死鎖，不涵蓋所有啟動後 GPU 停滯。沒有更動系統音訊服務、WebKit defaults、驅動、vault、chain 或既有 session。

不要重複 dispatch 此版號、覆寫 tag，或使用 Stable 重建 workflow 補建 Beta。
