# Lunport 1.3.0 validation

This release adds synced Group ordering, a unified Known hosts manager and manual saved-host TCP checks. [Feature validation](../2026-10-17-library-management-validation.md) records the implementation contracts, actual v1.2.0 compatibility harness, native Development App review and cleanup.

PR [#34](https://github.com/ysya/lunport/pull/34) merged as `2a0726a36fe220a8c93dba50361c7e1b6c45527a`. Its product sources match tested head `ff59d63779db0781a40cead7e521a2922ae340ee` exactly across `src/`, `src-tauri/`, package.json and pnpm-lock.yaml. The [frontend/macOS/Linux suite](https://github.com/ysya/lunport/actions/runs/39041031213) and [Windows suite](https://github.com/ysya/lunport/actions/runs/39041031243) pass. This includes real OpenSSH, Linux PAM, isolated macOS Keychain checks, native Windows startup, console helpers and published-v1.2.0 decoder compatibility. The full local safe macOS suite passed 2,621 tests with zero failures, one ignored and ten credential/PAM tests delegated to isolated CI.

The release branch changes package.json, Tauri config, Cargo.toml, the Cargo.lock root package and the release manifest to 1.3.0. Product behavior, dependencies, updater public key, bundle/executable/service identities and the fixed macOS signing certificate remain unchanged during release preparation.

Version-stamped candidate `06bfe66a1d76c38a8f5ed3153be27f1b6e390d40` passes TypeScript, all 86 frontend files / 1,078 tests and the production frontend build locally. Its [frontend/macOS/Linux suite](https://github.com/ysya/lunport/actions/runs/39043556798), [Windows suite](https://github.com/ysya/lunport/actions/runs/39043556782) and [DEB/RPM upgrade checks](https://github.com/ysya/lunport/actions/runs/39043556786) all pass. Release PR [#35](https://github.com/ysya/lunport/pull/35) merged as `922d278bfef86bbaee4e709e8f8232e1bc33d581`; its complete tree exactly matches that tested release candidate. [CI snapshots](1.3.0-review/ci/) retain exact sources and step results.

Account wire schema remains 4 and Group payload schema remains 1. Group ordering uses an independent encrypted metadata record; v1.2.0 clients retain it and continue normal sync. The local cache upgrades to state version 5 with an exact previous-state backup. Mixed-device sync compatibility does not imply local binary downgrade compatibility: restoring an older binary requires restoring that backup.
