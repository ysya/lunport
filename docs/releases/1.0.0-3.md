# SSHelter 1.0.0-3 (beta)

This beta adds nested Groups, Records MCP command execution and human-confirmed public-key deployment. It includes the restored Settings and AI Access entry points, compact server-identity confirmation and restrained scrollbars from the previous beta, and makes native selects follow the app's light/dark theme.

## Changes

- Organize Local and shared hosts in nested Groups. Choose inheritance beside each host setting, see effective values and their source, and retain explicit host overrides. Deleting a Group materializes affected hosts' effective settings; moving scopes preserves their behavior. If host or Group settings change while deletion is being reviewed, refresh and explicitly confirm again.
- Run Records MCP `ssh_exec` through SSHelter's own SSH engine. AI Access defaults to Ask, shows the effective destination, route, full command and OS-observed requester, and exposes only individually permitted stable host IDs. Self-reported MCP client information is labeled separately.
- Provide native password, passphrase and keyboard-interactive questions with hop attribution, cancellation and expiry. Ask approval defaults to Deny. Responses are discarded when questions change, expire or are abandoned.
- Offer explicitly acknowledged Auto-log mode, bounded execution/output, cancellation and public session history. Unknown exit status, signals, disconnects and timeouts retain their actual outcomes. An audit write failure is visible and never automatically reruns a completed command.
- Deploy a selected public key from Keys to a saved POSIX remote account after reviewing the effective destination, route and fingerprint. Previews are bound to the authoritative host and public-key identity and are single use. Existing authorized_keys content and key restrictions are preserved; duplicates and symlink paths are handled explicitly.

## Before using Groups or inheritance

Existing ungrouped state version 3 and host schema 2 remain supported. First use of a Group or inherited settings requires confirmation and promotes local state to version 4 after saving a protected source-state backup. Shared Groups require account schema 4 to be acknowledged before dependent records upload.

Stop older clients or update every device before confirming this upgrade. A format marker cannot recall an older client's in-flight write. Keep the protected backup and do not downgrade Group-capable data to an older client. The state backup contains record state; it is not a backup of the encrypted local vault or OS-stored credentials, and restoring local files alone does not undo a completed shared upgrade.

## Compatibility and limits

The accountless sync-chain architecture is unchanged: each device keeps its encrypted vault and master key locally. The relay holds end-to-end encrypted shared records and explicitly selected private keys; SSH passwords and key passphrases remain local. Relay 0.2.0 with pull-batch/freeze supports Groups without a relay update.

Existing saved relay settings are retained. If the build has no built-in relay, enter your relay URL in Sync account before creating or joining a chain. The supplied SSHelter relay is https://sshelter-relay.ysyavv.workers.dev; external relays require HTTPS.

Auto-log never opens authentication or server-identity prompts. Windows supports verified no-prompt reads of existing stored credentials; missing credentials and unpinned identities still require Ask. Credential-dependent Auto-log requests on macOS/Linux currently fail closed because their credential providers have no verified no-prompt read path. Ask remains available. Starting hidden does not lift the human-activation credential gate merely because an MCP approval window appears.

Public-key installation requires a POSIX remote shell and utilities. Windows clients can target POSIX hosts; installing keys on a remote Windows account is unsupported. Cancellation, timeout or transport loss after dispatch can leave the remote installation result unknown; inspect the remote account before retrying. Installing a public key does not change the saved host's authentication settings or grant MCP access.

MCP is a same-user OS IPC boundary, not a sandbox against another program running as that user. Group membership does not grant AI access to every host. The Records adapter uses the new MCP protocol; old Records `run` requests report that it was renamed to `ssh_exec`, while existing Connect protocol compatibility is retained.

Changing a sync code routes future updates to a new chain; old code holders can still read frozen historical ciphertext and previously downloaded data cannot be revoked. Anyone holding a chain's code can access records and keys shared into that chain.

This prerelease is offered through the Beta update channel. Stable remains unchanged. Windows native-select theme declarations are covered by code/cascade checks; actual Windows popup appearance still requires device acceptance.
