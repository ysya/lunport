# SSHelter 1.0.0-2 (beta)

This beta restores the settings and MCP entry points in the records workspace and improves everyday host editing.

## Changes

- Restore Settings, AI Access (MCP), preferences shortcuts, quick connect, terminal preferences, startup preference synchronization and update checks.
- Keep host drafts when switching sections, confirm before replacing a draft, and keep save/discard/connect actions visible while scrolling. Group advanced SSH settings and host management separately.
- Show the host sidebar only in Hosts; keep search fixed above the host list. Use thinner, neutral scrollbars across the workspace and settings.
- Distinguish Local-only operation, pending sync setup and last-sync status. Put relay setup before creating or joining an accountless sync chain.
- Restore explicit Records MCP host permissions using stable IDs and sanitized metadata. Legacy alias permissions do not automatically grant access to Records hosts. Revoking access remains independent of a running command's lifecycle lock.

## Compatibility and limitations

No vault, record or relay protocol migration is introduced by this update. The existing relay 0.2.0 with `pull-batch` and `freeze` supports this beta.

Records MCP supports `list_hosts` and `get_effective_config` for explicitly allowed hosts. **MCP remote command execution and key deployment are still unavailable in the records workspace.** The AI Access page states this limitation; restoring its entry point does not enable remote execution. MCP exposes only explicitly selected host IDs while AI Access is enabled.

The migration, private-key sharing and sync-code history limitations described in [1.0.0-1](https://github.com/ysya/sshelter/releases/tag/v1.0.0-1) still apply. This is a Beta-channel prerelease; Stable remains unchanged.
