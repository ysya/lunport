# Lunport 1.2.0 validation

The release combines a full-height Library sidebar, SSH key renaming and stable macOS Keychain authorization. Product sources in integrated main `30f692d361b2fb13e2a47381765d9761ac240ac9` match tested candidate `8ba9339efb5f20e62299f4bca7e87ee384099332` exactly across `src/`, `src-tauri/`, package.json and pnpm-lock.yaml. The release branch changes version fields to 1.2.0 and adds release documentation; no application behavior is changed during release preparation.

## Library and key names

- Native macOS Development App: the sidebar spans the full window height. Collapse/expand, right-side Settings and Sync, and the host-page Import hosts button work. At the 800×560 minimum viewport, the sidebar spans the full height, the toolbar/statusbar stay in the content column and the document has no horizontal overflow. Reduced-motion rules remain effective.
- A disposable Development key was renamed through the native UI. The new label survived an app restart; fingerprint and public key remained identical. The original fixture name was restored and the test App quit normally. Production data was not used.
- Four focused native tests verify stable key/vault/host identity, monotonic account metadata revisions and queued sync, missing-material account keys, stale edits, invalid names, write gates, deleted keys and conflicting material. Rename never opens the vault or changes private-key sharing.
- Local integrated macOS safe Rust suite: 2,605 passed, zero failed, one CI-only native test ignored and ten credential/PAM tests filtered. The real OS credential assertions run separately in an isolated CI keychain.

## Signing and compatibility

[Keychain validation](../2026-10-17-keychain-update-trust.md) records the fixed project certificate, actual universal App/updater verification, same-signer upgrade access and rejection of an ad-hoc replacement. Stable and Beta retain the same project identity. This does not provide Apple Developer ID or notarization; migration from an old unsigned build can still require one-time authorization.
