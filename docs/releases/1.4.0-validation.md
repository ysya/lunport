Actual-component visual checks and screenshots are recorded in the [protocol/username preview](../ui-review/2026-10-18-protocol-username/README.md) and [color-theme review](../ui-review/2026-10-18-color-themes/README.md).

Release PR [#37](https://github.com/ysya/lunport/pull/37) sets package.json, Tauri config, Cargo.toml, the Cargo.lock root package and the release manifest to 1.4.0. Version-stamped candidate `1780fdf1a0270f145cd3106aec5a06ff34225055` passes TypeScript, 88 frontend test files / 1,093 tests and the production Vite build locally. The existing bundle-size advisory remains.

The candidate's [frontend/macOS/Linux suite](https://github.com/ysya/lunport/actions/runs/39068114908), [Windows suite](https://github.com/ysya/lunport/actions/runs/39068114645) and [Linux DEB/RPM upgrade checks](https://github.com/ysya/lunport/actions/runs/39068114658) all pass. This includes real SSH/PAM, isolated Keychain update authorization, Windows native startup and console helpers, profile isolation and published-v1.2.0 sync compatibility. The optional diagnostic Windows probe is skipped by the normal workflow; its standard native tests run inside the passing slots job.

The release PR merged as `2e091fab86a6b86ba91462b1a9039e83959ffc71`. Its full Git tree exactly matches the tested release candidate. Product/native behavior, dependencies, updater configuration, bundle/executable/credential identities, Folded L icon and fixed macOS signing certificate are unchanged during release preparation. ## Published 2026-10-17

[Lunport 1.4.0](https://github.com/ysya/lunport/releases/tag/v1.4.0) is published as Stable, release ID `416058956`. Tag `v1.4.0` points to the exact release source above. The [official release workflow](https://github.com/ysya/lunport/actions/runs/39069600318) passed all six jobs: release creation, universal macOS, Windows x64, Linux x64, Linux ARM64 and the Beta manifest.

[Publication receipts](1.4.0-review/publication/verification.json) verify all 20 uploaded, nonempty assets against their GitHub byte sizes and SHA256 digests. All nine updater payloads authenticate with the existing public key; modified copies are rejected with legacy signatures disabled. All 15 platform aliases resolve to verified artifacts. Stable, Beta and both original SSHelter updater endpoints offer the same 1.4.0 manifest, using the shipped updater headers without cache-busting query parameters.

The [downloaded macOS bundle](1.4.0-review/publication/macos-verification.json) passes strict, deep, all-architecture signature verification. Intel and Apple Silicon embed the existing pinned certificate and stable `org.homelab.sshelter` designated requirement. Bundle version 1.4.0, the executable identity and Folded L icon match the release source. Verification did not launch or install the Production App or import credentials into the user's Keychain.

Historical v1.0.0, v1.1.0, v1.2.0, v1.3.0 and v1.3.1-1 release bodies, asset identities/sizes/digests and tag targets remain unchanged. Installers stay in the temporary verification directory; the repository retains metadata, manifests and public signatures.
